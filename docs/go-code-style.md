# Goコード記述ルール

本ドキュメントでは、Goファイル内の宣言順序とメソッドコメントのルールを定めます。既存の `handler.go` の構成を基本とします。

## ファイル内の並び順

Goファイル内の宣言は、次の順序で配置します。

1. `package` 宣言
2. `import` 宣言
3. 構造体、インターフェース、その他の型定義
4. 公開メソッド
5. 非公開メソッド

### 型定義

構造体やインターフェースなどの型定義は、ファイルの上部にまとめます。関連するリクエスト・レスポンス用の構造体や、依存するサービスのインターフェースもここに配置します。

```go
type userService interface {
	GetUser(id int64) (User, error)
}

type createRequest struct {
	Name string `json:"name" binding:"required"`
}
```

### 公開メソッド

外部パッケージから利用する公開メソッドは、型定義の直後から非公開メソッドの前までにまとめます。公開メソッドが複数ある場合は、一覧、単件取得、作成、更新、削除など、機能の流れが分かりやすい順に配置します。

```go
// Create ユーザーを作成するサービスメソッド
func (s *Service) Create(input CreateInput) (User, error) {
	// ...
}
```

### 非公開メソッド

パッケージ内部だけで利用する非公開メソッドは、ファイルの末尾にまとめます。入力値の解析、変換、検証などの補助処理もここに配置します。

```go
// parseID パスパラメータからIDを解析する
func parseID(value string) (int64, error) {
	// ...
}
```

## メソッドコメント

すべてのメソッドには、メソッドの直前に、そのメソッドが何をするものかを説明するコメントを必ず付けます。コメントは処理の実装詳細ではなく、メソッドの責務と主な結果が分かる内容にします。

- コメントは対象メソッドの直前に置く
- 公開メソッドのコメントは、Goの慣例に従いメソッド名から始める
- 非公開メソッドにも同じようにコメントを付ける
- コメントが複数行になる場合は、各行を `//` で始める
- コメントだけでメソッドの目的が分かるようにする

```go
// GetUser 指定されたIDのユーザーを取得する
func (s *Service) GetUser(id int64) (User, error) {
	// ...
}

// validateUserInput ユーザー入力を検証する
func validateUserInput(input CreateInput) error {
	// ...
}
```

## 実装時の確認事項

新しいメソッドを追加するときは、次を確認します。

- メソッドのコメントが直前にある
- 公開メソッドか非公開メソッドかに応じて、ファイル内の正しい位置にある
- 構造体やインターフェースをメソッドの間に追加していない
- `gofmt` を実行している
